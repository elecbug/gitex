# GiTex

[English](README.md) | 한국어

한 시점에 한 명의 본문 작성자와 여러 검토자가 LaTeX 논문의 구절별 의견을 주고받는 비동기 Git 리뷰용 VS Code 확장입니다. LaTeX Workshop 등 기존 편집·컴파일·PDF 미리보기 환경과 함께 사용합니다.

## 주요 기능

- 기존 Git 저장소 열기, 복제, 충돌이 없는 현재 폴더에 저장소 적용
- workspace 하위 Git 저장소 재귀 탐색 및 선택한 파일에 따라 코멘트·동기화 대상 전환
- 주석 공유용 remote 선택·추가
- `.tex`, `.bib`, `.sty`, `.cls`, `.ltx`에서 드래그한 텍스트에 주석 작성; 선택이 없을 때만 현재 줄 전체 사용
- 답글 작성 및 Explorer·리뷰 패널의 해결 체크박스; 해결된 주석은 Explorer에 남기고 본문에서 숨기기
- 주석과 답글 편집, 원문 및 모든 편집 이력 보존
- 새 주석·답글·편집 저장 직후 한 번 자동 pull·병합·push; 기본 활성화, 설정으로 변경 가능
- 새 본문 커밋마다 주석 상태를 기록하고 현재 문서 커밋의 내용·위치·해결 상태 표시
- Explorer의 **GiTex Comments**와 VS Code **Comments** 패널에서 주석 확인
- 편집기의 삽입·삭제·같은 파일 내 잘라내기와 붙여넣기·실행 취소를 따라 선택 범위 추적
- 선택 범위가 분리되면 앞쪽 조각에 코멘트를 표시하고 최초 선택 전체와 이전 기준은 보존
- 선택한 본문으로 코멘트 수동 이동, 같은 저장소의 다른 파일로 이동 및 전체 이동 이력 보존
- 리뷰 탭 하나를 재사용하고 스레드 전환 시 작성 중인 편집·답글 초안 보존
- 같은 편집 세션의 잘라낸 대상은 **Uncertain**, 저장 후 세션이 끝날 때까지 복원되지 않은 대상은 **Outdated**로 표시
- 원래 주석 조각은 밝은 노란색, 사이에 삽입된 본문은 하늘색 음영으로 표시하며 클릭하면 코멘트 열기
- 문서보다 먼저 받은 코멘트는 **Pending document**로 대기시키고 본문 pull 안내
- 오프라인 주석 저장 및 중앙 bare 저장소를 통한 여러 사용자의 주석 동기화

논문 커밋·push/pull·병합은 VS Code의 **Source Control**을 사용합니다. **Sync Comments**와 저장 직후 자동 동기화는 원격 주석을 자동 pull·병합한 뒤 공유합니다. 현재 문서 커밋의 주석을 갱신하며 본문 최신 커밋으로의 업데이트는 요구하지 않습니다. 두 동작 모두 편집 중인 파일, 현재 브랜치, 스테이징 영역을 변경하지 않습니다.

## 지원하는 협업 모델

**본문 수정은 한 시점에 한 명이 맡고, 여러 검토자는 코멘트와 답글을 동시에 작성합니다.** 작성자가 본문 커밋 H1을 push하면 검토자 B·C·D가 동일한 H1을 pull해 병렬로 리뷰하고, GiTex가 독립적인 리뷰 이벤트를 자동 병합합니다. 작성자는 리뷰를 수집한 뒤 본문을 수정하고, 리뷰 상태를 상속한 다음 버전 H2를 만듭니다.

이 협업 모델에는 두 가지 조율 규칙이 있습니다.

1. 본문 작성 담당자를 바꿀 때는 기존 담당자가 본문을 커밋하고 본문·리뷰를 동기화한 뒤, 새 담당자가 합의한 버전을 pull하고 수정합니다. 작성자는 고정할 필요가 없으며 검토자끼리는 리뷰 순서를 기다릴 필요가 없습니다.
2. H2의 리뷰를 처음 게시하기 전에 검토자들이 H1 코멘트를 공유하고 작성자가 수집을 마칩니다. 새 로컬 커밋에서 리뷰 자동 게시가 실행될 수 있으므로 H2를 만들기 전에 H1 리뷰를 수집하는 절차를 권장합니다. 첫 게시 이후 H1에 늦게 도착한 의견은 H1에 남고 H2로 자동 상속되지 않습니다.

이는 팀이 지키는 작업 규칙이며, 확장이 본문을 잠그거나 실시간 공동 편집을 제공하는 것은 아닙니다. 주석 작성에 깨끗한 작업 트리나 선행 커밋을 강제하지 않습니다. 미저장·미커밋 본문의 주석은 그 버전을 받지 못한 사용자에게 **Pending document**로 대기할 수 있습니다. 논문 작성자와 지도교수·공동저자가 비동기로 리뷰하는 범위의 안정화를 우선하며, 별도의 문서 동시 편집 알고리즘을 추가하는 방향을 전제로 하지 않습니다. 인계·첫 게시·대기 상태의 상세 규칙은 영어 [지원 협업 모델 문서](docs/collaboration-model.md)에 정리했습니다.

## 아키텍처와 협업 흐름

각 사용자는 VS Code에서 로컬 작업 사본을 유지합니다. 공동 Git 원격 저장소는 논문 본문과 리뷰 이력을 각각 별도의 브랜치에 보관합니다. 그림에서는 사용자 A가 논문을 작성하고 사용자 B가 검토하며, 위의 인계 절차를 통해 본문 작성 역할을 바꿀 수 있습니다.

![GiTex 아키텍처: 두 VS Code 사용자가 공동 bare Git 저장소의 Main Branch로 LaTeX 문서를, GiTex Branch로 리뷰 주석을 공유하는 구조.](docs/images/architecture.png)

초록색 **Edited Data**는 해당 사용자가 편집한 데이터를, 파란색 **Synced Data**는 다른 협업자의 데이터를 Git으로 받아 온 상태를 나타냅니다.

| 그림의 구성 요소 | GiTex에서의 역할 |
| --- | --- |
| **Git Bare Repository** | 공동 원격 저장소입니다. 직접 운영하는 bare 저장소나 GitHub 같은 Git 호스팅 서비스를 사용할 수 있으며, 각 사용자는 로컬 작업 사본을 갖습니다. |
| **Main Branch** | LaTeX 소스, 참고문헌, 그림 등을 저장하는 `main` 등의 일반 논문 브랜치입니다. 본문 커밋·pull·push·병합은 일반 Git이나 VS Code Source Control로 처리합니다. |
| **GiTex Branch** | GiTex 전용 원격 브랜치 `gitex-comments`(`refs/heads/gitex-comments`)입니다. 코멘트·답글·편집·위치 이동·해결 상태를 불변 이벤트로 저장합니다. 로컬 리뷰 이력은 `refs/gitex/comments`에 보관합니다. |

그림의 협업 과정은 다음과 같습니다.

1. **논문 작성과 공유:** 사용자 A가 로컬에서 LaTeX 문서를 편집하고 커밋한 뒤 논문 브랜치를 push합니다.
2. **본문 검토:** 사용자 B와 다른 검토자들이 동일한 논문 커밋을 pull하고, 그림의 14번째 줄 오탈자처럼 검토할 구절에 동시에 GiTex 코멘트를 작성할 수 있습니다.
3. **리뷰 이벤트 공유:** 코멘트를 저장하면 먼저 로컬 이력에 기록합니다. 자동 동기화가 켜져 있으면 이어서 원격 주석을 pull·병합하고 합쳐진 이력을 백그라운드에서 `gitex-comments`로 push합니다.
4. **수정과 반복:** 검토자들이 해당 회차의 의견을 공유하면 사용자 A가 **Sync Comments**로 이를 수집하고 로컬 답변도 공유한 뒤 다음 본문 커밋을 만듭니다. 답글·편집·해결 상태는 리뷰 이력에 남으며, 본문 수정본은 계속 일반 논문 브랜치로 공유합니다.

그림의 **“Sync comments on refresh”**는 사용자가 Explorer의 **GiTex Comments** 창에서 직접 공유된 리뷰를 갱신하는 흐름을 뜻합니다. 창 상단의 **Sync Comments** 버튼으로 원격 주석을 자동 pull·병합하고 로컬 리뷰 이벤트도 공유합니다. 별도의 **Refresh Comments** 버튼은 로컬 데이터를 다시 읽으며, 원격 리뷰 받기만 수행하려면 **Fetch Comments** 명령도 사용할 수 있습니다.

자동 동기화는 코멘트·답글·편집·수동 위치 이동을 저장한 직후 한 번 실행합니다. 설정과 실행 조건은 [저장 직후 자동 동기화](#저장-직후-자동-동기화)를 참고하세요. 사용자 사이의 점선 검토 요청은 협업자 간 의사소통을 나타내며, 확장에 내장된 알림이나 승인 서비스를 뜻하지는 않습니다.

원격 응답이나 스냅샷 공유 승인을 기다리는 동안에도 새 주석을 로컬에 저장할 수 있습니다. Sync는 실제 push 대상에서 먼저 주석을 받아 병합하고, Fetch Comments는 fetch 주소를 사용합니다. push 중 새로 저장된 주석은 **Sync pending**으로 남겨 다음 동기화가 필요함을 표시합니다. 책임 분리와 검증 범위는 영어 [아키텍처 검토 문서](docs/architecture-review.md)에 정리했습니다.

## 설치와 사용

필요한 환경은 VS Code 1.90 이상, Git, 로컬 논문 저장소입니다. LaTeX 컴파일에는 기존에 사용하던 LaTeX 확장과 TeX 배포판이 필요합니다.

1. VS Code 명령 팔레트에서 **Extensions: Install from VSIX…**를 실행하고 `gitex-0.15.4.vsix`를 선택합니다.
2. 논문의 로컬 Git 저장소 또는 여러 저장소를 포함한 상위 폴더를 열고 논문 파일을 선택합니다. 새로 복제하려면 **GiTex: Clone Repository**, 이미 열린 폴더에 적용하려면 **GiTex: Apply Repository to Current Folder**를 실행합니다.
3. Git 작성자 이름과 이메일이 설정되어 있어야 합니다.

   ```sh
   git config user.name "Your Name"
   git config user.email "you@example.com"
   ```

4. 기본 remote는 `origin`입니다. 다른 remote를 사용하거나 추가하려면 **GiTex: Connect Repository**를 실행합니다.
5. 논문 파일에서 대상 텍스트를 드래그한 뒤 **Ctrl+Shift+/** (macOS: **Cmd+Shift+/**)를 누르면 주석 입력창이 열립니다. 선택 영역이 없을 때만 커서가 있는 줄 전체에 작성합니다. 우클릭 → **GiTex: Add Comment** 또는 편집기 왼쪽 주석 버튼으로도 작성할 수 있습니다. 빈 줄이나 공백·탭만 있는 줄에는 새 주석 버튼이 나타나지 않으며, 빈 줄만 선택하면 입력창을 열기 전에 거절합니다. 본문이 있는 줄에서도 공백만 선택하면 입력 전에 거절합니다.
6. 주석·답글·편집을 저장하면 백그라운드에서 자동 동기화합니다. 받기만 하려면 **GiTex: Fetch Comments**, 수동으로 검사하고 공유하려면 **GiTex: Sync Comments**를 실행합니다.
7. 논문 본문 변경은 Source Control에서 커밋하고 동기화합니다.

본문에서 펼친 인라인 코멘트에도 **Reply** 옆에 **Sync** 버튼이 있습니다. Explorer의 **Sync Comments**와 동일하게 해당 코멘트가 속한 저장소의 저장된 리뷰 이벤트 전체에 동일한 자동 pull·병합·push 규칙을 적용하며, 자동 동기화를 꺼도 사용할 수 있습니다. 작성 중인 답글을 보호하기 위해 답글 입력칸이 비어 있을 때만 활성화합니다. 답글을 작성하는 동안에는 Explorer의 **Sync Comments**를 사용할 수 있습니다.

파일이 디스크에 존재하면 저장하지 않은 편집 내용에도 주석을 달 수 있습니다. 선택한 텍스트만 저장하며 첫 줄과 마지막 줄의 일부만 선택한 경우도 그대로 반영합니다. 다른 사용자가 해당 문서 버전을 아직 받지 않았다면 **Pending document**로 대기하고 본문에는 표시하지 않습니다.

단축키는 편집 가능한 로컬 `.tex`, `.bib`, `.sty`, `.cls`, `.ltx` 파일의 본문에 포커스가 있을 때 동작합니다. 단축키를 바꾸려면 VS Code의 Keyboard Shortcuts에서 `GiTex: Add Comment`를 검색하세요.

네트워크 인증은 Git의 SSH 에이전트나 HTTPS 자격 증명 도우미를 사용합니다. 먼저 같은 환경의 터미널에서 `git ls-remote origin`이 성공하는지 확인하면 됩니다. 원격 서버에는 `gitex-comments` 브랜치를 읽고 쓸 수 있는 권한이 필요합니다.

## 선택한 파일을 기준으로 저장소 전환

GiTex는 열린 모든 로컬 workspace 폴더 아래에서 Git 저장소를 재귀적으로 찾습니다. workspace 루트 자체가 Git 저장소일 필요는 없습니다. 예를 들어 `papers/`만 열어도 `papers/project-a/main.tex`와 `papers/group/project-b/main.tex`를 각각 선택해 해당 저장소에서 작업할 수 있습니다. 중첩 저장소나 서브모듈에서는 파일을 감싸는 가장 가까운 Git 작업 트리를 사용합니다. `.git`이 파일인 worktree도 인식합니다.

**GiTex Comments**에는 현재 선택한 파일의 저장소에 속한 모든 스레드를 표시하며, 해결됨·대기 중인 코멘트도 포함합니다. 목록 제목 옆에 저장소 경로를 표시합니다. 인라인 코멘트, 상태 표시줄의 개수, **Connect Repository**·**Fetch Comments**·**Sync Comments**의 대상도 같은 저장소로 전환합니다. workspace의 Git 작업 트리에 속하지 않는 파일을 선택하면 목록을 비웁니다. Explorer나 리뷰 탭으로 포커스를 옮기면 본문에서 선택한 저장소를 유지하고, GiTex 이력 문서를 열면 해당 코멘트의 저장소를 유지합니다.

이미 열린 리뷰 탭은 열어 둔 스레드를 유지하며, 코멘트 위에 저장소를 표시합니다. 다른 스레드를 선택하면 같은 탭을 재사용합니다. 파일을 전환해도 초안과 진행 중인 저장 작업은 원래 저장소에 연결되며, 전환만으로 pull/push하지 않습니다. `gitex.remote`·`gitex.autoSyncOnSave` 등의 설정은 저장소가 속한 workspace 폴더에서 가져오므로, 같은 workspace 폴더 아래의 저장소들은 이 설정을 공유합니다.

탐색 중 Git 내부 데이터, bare 저장소 내부, GiTex 임시 적용 폴더와 디렉터리 심볼릭 링크는 건너뜁니다. 저장소 하나를 발견해도 그 아래의 중첩 저장소를 계속 탐색합니다. 저장소의 하위 폴더만 열어도 상위 저장소를 인식하되, 열린 폴더 바깥을 재귀 탐색하지는 않습니다. 본문 편집 중에는 탐색 결과를 재사용하고, 파일 전환 시 Git으로 소속을 확인합니다. workspace 또는 `.git` 변경 시 다시 탐색하며, 외부에서 clone·삭제한 변경을 파일시스템 알림이 놓쳤다면 **GiTex: Refresh Comments**로 수동 재탐색할 수 있습니다.

## 주석 편집과 이력 보기

자신이 작성한 인라인 주석이나 답글에서 **Edit Comment**를 선택하고 내용을 변경한 뒤 **Save Edit**로 저장합니다. **Cancel Edit**는 입력 중인 초안을 취소합니다. 최신 저장 내용에는 **Edited** 표시가 붙습니다. **View Edit History**는 원문부터 모든 편집 내용과 각 버전의 편집자·시간을 읽기 전용 문서로 보여줍니다.

인라인 저장에 실패하면 VS Code가 입력창을 닫더라도 초안을 복구할 수 있도록, GiTex가 리뷰 패널을 열어 입력 중이던 내용을 그대로 표시합니다.

**GiTex Comments**에서 스레드를 클릭하거나 인라인 스레드의 **Open GiTex Review**를 선택하면 리뷰 패널이 열립니다. 다른 스레드를 선택하면 같은 탭의 내용을 교체하며, 탭을 닫지 않고 돌아오면 해당 스레드의 편집·답글 초안과 펼침 상태가 복원됩니다. 이 패널에서 편집, 답글 작성, **History** 펼치기가 가능합니다. **Open source**로 해당 문장을 열고, 문서가 대기 중이면 **Open saved excerpt**로 저장된 발췌문을 열 수 있습니다. 주석 삭제 기능은 제공하지 않습니다.

주석과 답글은 각각 작성자의 Git 이메일이 일치할 때만 본문을 편집할 수 있습니다. 타인의 주석에는 답글을 달 수 있고, 위치 이동과 해결 상태 변경도 협업할 수 있습니다. 같은 작성자가 여러 기기에서 동시에 편집하면 모든 버전을 보존하고 **Concurrent edits**를 표시합니다. 작성자가 History를 확인한 뒤 편집을 다시 열어 원하는 내용을 저장하면 충돌 버전을 정리합니다. 보지 못한 충돌 버전은 오래된 초안으로 덮어쓰지 않습니다. 형식 1–3을 계속 읽고 다음 쓰기에서 형식 4로 이전하며, 개별 이벤트·추적 데이터는 버전 1을 유지합니다. 형식 호환성은 GiTex 0.15.0 이상, 현재의 추적·공유 보호 정책은 협업자 모두 0.15.2 이상을 권장합니다.

## 리뷰 패널 구성

리뷰 패널은 VS Code의 밝은·어두운·고대비 테마를 따르며 좁은 편집기 분할 화면에 맞춰 배치됩니다. 상단 카드에서 저장소, 파일 경로, 현재 줄 범위와 연결 상태를 확인할 수 있습니다. **Saved reference**를 펼치면 추적 기준 본문이 나타납니다. 저장된 기준이므로 최근 수정 후 근사 매칭된 실제 본문과 다를 수 있습니다. 바로 아래에는 본문 열기, 수동 위치 이동, **Resolved** 체크박스를 모았습니다.

코멘트마다 작성자, 작성 시각과 편집 여부를 표시합니다. 편집 이력과 추적 이력은 필요할 때 펼치며, 최신 항목부터 보여 주고 현재 버전을 별도로 표시합니다. 넓은 패널에서는 수동 이동 전후의 기준을 나란히 비교할 수 있습니다. 탭을 닫지 않고 스레드를 전환하면 초안·펼침 상태·스크롤 위치를 유지합니다.

**0.15.3부터 Discussion**에는 코멘트·답글과 함께 수동 위치 이동도 기록 순서대로 표시합니다. **Location moved**는 수정할 수 없는 읽기 전용 항목이며, 이동한 사람·시각과 이동 전후의 파일·줄 범위를 보여 줍니다. **Moved passages**를 펼치면 당시 저장된 구절을 확인할 수 있습니다. 자동 위치 추적 갱신은 Tracking history에서 확인합니다.

답글이나 편집 입력창에서 **Ctrl+Enter**(macOS는 **Cmd+Enter**) 또는 저장 버튼으로 저장합니다. 빈 답글은 저장할 수 없으며, 로컬 저장이 진행되는 동안 **Saving…** 표시와 함께 중복 제출을 막습니다. 동기화 표시는 저장 후 자동 동기화, 수동 동기화, 동기화 실패 상태를 구분하며 펼쳐서 자세한 안내를 볼 수 있습니다. 이 UI를 열거나 펼치는 것만으로 원격 요청을 보내지는 않습니다.

## 해결 체크박스

리뷰 패널의 **Resolved**, 또는 **GiTex Comments**의 스레드 옆 체크박스를 체크하면 LaTeX 편집기에서 해당 코멘트가 사라집니다. Explorer에는 해결 상태와 이력을 유지하며 계속 열람할 수 있습니다. 체크를 해제하면 위치를 찾을 수 있는 코멘트가 본문에 다시 나타납니다. 기존 인라인 **Resolve Thread**·**Reopen Thread**도 같은 상태를 변경합니다.

인라인 코멘트를 편집하다 해결해도 초안은 리뷰 패널에서 복구할 수 있습니다. 이전 `gitex.showResolved` 설정은 폐기 예정이며 더 이상 필터로 사용하지 않습니다. 해결된 코멘트는 항상 Explorer에 남고 본문에서는 숨깁니다. 해결/다시 열기는 로컬에 저장하고, 다음 코멘트 저장 또는 수동 **Sync Comments** 때 공유합니다. 저장 직후에만 자동 동기화하는 기존 규칙은 유지합니다.

## 편집 이력에 따른 위치 추적

GiTex 0.15.2은 VS Code의 편집 이벤트로 범위를 이동합니다. 선택 앞의 삽입·삭제는 시작점과 끝점을 함께 이동시키고, 끝에 덧붙인 문장은 주석 범위에 포함하지 않습니다. 같은 파일에서 식별 가능한 유일한 텍스트를 잘라 붙이면 새 위치로 따라갑니다. 짧거나 반복되는 텍스트는 동일 편집 이벤트에서 삭제·삽입이 유일하게 대응할 때만 이동하며, 그 외에는 Uncertain으로 남깁니다. 문서 간 Diff는 양방향 정렬 결과를 비교하고 대응이 모호하면 자동으로 연결하지 않습니다. 복사만 해서는 기존 코멘트가 이동하지 않으며, 실행 취소와 다시 실행은 이전 범위를 복원합니다.

선택 내부에 줄바꿈이나 공백만 추가하면 여러 줄에 걸친 하나의 범위로 유지합니다. 다른 본문을 삽입하여 A–B가 A–C와 C–B로 분리되면 원래 앞쪽 조각 A–C에 코멘트를 표시합니다. 전체 A–B는 **Original selection**에, 나머지 조각은 추적 데이터에 보존합니다. 답글·편집 저장은 현재 기준을 공유하되 최초 선택을 교체하지 않습니다. 명시적인 수동 이동만 새 정체성 기준을 만들며 이전 기준은 **Tracking history**에 남습니다.

대상 전체를 잘라내면 같은 편집 세션 동안 삭제 위치에 **Uncertain** 표시를 유지합니다. 저장만 해서는 잘라낸 정보가 만료되지 않으며, 위의 식별·유일성 조건을 충족하는 같은 세션의 붙여넣기는 새 위치로 코멘트를 이동합니다. 대상이 없는 상태로 저장한 뒤 해당 파일의 마지막 텍스트 탭을 닫거나 VS Code를 재시작하면 **Outdated**로 확정하여 Explorer와 Review에만 남깁니다. 코멘트가 문서보다 먼저 도착하면 Explorer와 Review에 **Pending document**로 표시하고 본문에서는 숨깁니다. Source Control에서 논문을 pull하세요. **Sync Comments**는 리뷰만 동기화합니다. 새로운 기준을 적용할 때는 현재 문서가 스냅샷과 일치하는지, 또는 해당 문서 버전이 현재 논문 브랜치 이력에 들어왔는지 확인합니다.

문서와 주석은 어느 순서로 동기화되어도 됩니다. 논문 버전을 전환하면 이미 표시했던 주석도 다시 검사합니다. pull이 디스크만 갱신하고 편집기에 오래된 미저장 본문이 남아 있다면 새 버전의 주석은 계속 대기합니다. 미저장 수정을 받은 본문과 병합하거나 정리한 뒤 표시할 수 있습니다. 주석 작성 후 설명을 덧붙여 커밋한 경우에도 양방향 정렬 모두에서 공통 기준 커밋의 변경분 전체가 같은 좌표에 반영됐는지 확인하고 연결합니다. 같은 커밋의 대기 중 답글은 기존 기준을 유지합니다. 다른 커밋에만 속한 주석을 편집하려면 먼저 해당 본문을 pull하거나 전환해야 하며, 주석 저장 도중 본문에 들어온 편집도 최신 스냅샷에 반영합니다. 구체적인 사례는 영어 [동기화 시나리오 문서](docs/anchor-tracking.md#6-comments-arriving-before-the-paper)를 참고하세요.

다른 사용자의 편집기 이력 없이도 기준 문서를 확인할 수 있도록, 메타데이터에는 주석을 단 소스 파일 전체의 스냅샷도 저장합니다. 저장하지 않은 본문 수정도 포함하며 같은 내용은 한 번만 저장합니다. 기존 이벤트는 계속 읽을 수 있지만 새 저장 형식 4를 공유하려면 협업자 모두 **GiTex 0.15.0 이상**이 필요합니다. 기준 문서를 복원할 수 없는 과거 코멘트는 **Move to editor selection**으로 다시 연결할 수 있습니다.

저장된 로컬 범위는 VS Code 재시작 후에도 복원됩니다. 파일 새로고침이나 닫힌 동안의 수정에는 알려진 스냅샷과의 정확한 편집 차이를 적용하며 문장 유사도로 대상을 재검색하지 않습니다. 잘라내기 연결은 같은 문서의 편집 세션에서 식별·유일성 조건을 충족하는 삭제·삽입에 적용합니다. 파일 사이 이동은 수동 이동 명령을 사용합니다. 구체적인 범위 규칙·저장 구조·대기 상태·호환성·한계는 영어 문서 [Anchor tracking design and implementation](docs/anchor-tracking.md)에 정리했습니다.

## 본문 음영과 클릭

해결되지 않은 코멘트의 원래 조각들은 밝은 노란색으로 계속 표시하며, 인라인 코멘트를 접어도 음영은 유지합니다. 분리된 조각 사이에 삽입한 본문은 하늘색과 점선 테두리로 구분합니다. 남아 있는 모든 조각을 칠하고 원래 선택 전체는 Review에서 확인할 수 있습니다. 두 색상 모두 클릭하면 코멘트를 열며 본문 편집기의 포커스는 유지합니다. 드래그로 선택하거나 키보드로 커서를 이동할 때는 열지 않습니다. 마우스를 올리면 구간 설명과 **Open comment** 링크도 표시합니다.

해결됨·Pending·Outdated 상태에는 본문 음영이 없습니다. 밝은 테마, 어두운 테마, 고대비 테마를 지원합니다. 색상은 VS Code의 `workbench.colorCustomizations`에서 `gitex.commentBackground`, `gitex.commentBorder`, `gitex.insertedBackground`, `gitex.insertedBorder`로 조정할 수 있습니다. 현재 추적 보호 정책은 협업자 모두 GiTex 0.15.2 이상을 권장합니다. 형식 호환성은 0.15.0 이상입니다.

## 코멘트 위치 수동 이동

1. 화면에 열린 `.tex`, `.bib`, `.sty`, `.cls`, `.ltx` 편집기에서 이동할 텍스트를 선택합니다. 선택 영역이 없으면 커서가 있는 줄을 사용합니다. 파일은 디스크에 존재해야 하며, 저장하지 않은 본문 편집도 반영합니다.
2. **GiTex Comments**에서 대상 스레드를 열고 리뷰 패널의 **Move to editor selection**을 누릅니다. Explorer의 해당 스레드 우클릭 또는 인라인 스레드 메뉴에서 **GiTex: Move Comment to Selection**을 실행해도 됩니다.
3. 명령 팔레트나 본문 우클릭 메뉴에서 **GiTex: Move Comment to Selection**을 실행한 경우에는 이동할 스레드를 선택합니다.

답글을 포함한 스레드 전체가 선택한 위치로 이동합니다. **Uncertain**·**Outdated**·**Pending document** 코멘트를 다시 연결하거나 같은 저장소 안의 다른 소스 파일로 이동할 수도 있습니다. 스레드 ID, 코멘트 내용, 편집 이력, 해결 상태는 유지합니다. 해결된 스레드는 이동 후에도 본문에서 숨깁니다. 인라인 코멘트를 편집 중이라면 먼저 저장하거나 취소해야 하며, 리뷰 패널의 초안은 이동해도 보존합니다.

성공한 이동은 매번 별도의 불변 이벤트로 기록하며, 같은 위치로 다시 이동해도 기록합니다. **Tracking history**에 **Manual move**로 표시하고, 이전 추적 기준과 새 위치의 파일·줄 범위·본문 및 이동한 사람·시간을 보여줍니다. 이후 자동 추적은 새 위치를 기준으로 합니다. 위치 이동도 코멘트 편집 저장으로 취급하여, `gitex.autoSyncOnSave`가 켜져 있으면 직후 한 번 백그라운드 pull·병합·push를 시도하고, 꺼져 있으면 로컬에만 저장합니다.

선택 도중 본문이나 이미 알고 있는 코멘트 위치가 바뀌면 이동을 거절하므로 다시 선택하세요. 오프라인에서 동시에 이동하면 양쪽 이동 전후를 모두 기록하고 일관된 순서로 현재 위치를 정합니다. 이전 위치에서 만든 자동 추적 갱신은 이력에 보존하되 수동 이동을 되돌리지 않습니다. 따라서 마지막 이력 항목이 현재 위치가 아닐 수도 있으며, **Current reference** 표시로 구분합니다.

문서 스냅샷이 있는 이동을 공유하려면 협업자 모두 **GiTex 0.15.0 이상**이 필요합니다. 기존 코멘트 내용과 추적 이력은 보존합니다.

## 저장 직후 자동 동기화

`gitex.autoSyncOnSave`의 기본값은 `true`입니다. 새 주석·답글·편집·수동 위치 이동을 성공적으로 저장하면 로컬 내용을 화면에 먼저 반영하고, 백그라운드에서 한 번 **pull → 병합 → push**를 시도합니다. 원격 주석이 앞서 있어도 자동으로 받아 병합하며, 본문 최신 커밋을 요구하지 않습니다. 열기·클릭·펼치기·포커스 이동·이력 보기·편집 시작/취소·해결/다시 열기는 원격 요청을 발생시키지 않습니다. **Refresh Comments**는 로컬 데이터만 다시 읽습니다. 주기적인 polling은 없습니다. 자동 동기화에도 첫 공유 확인과 스냅샷 공유 설정이 적용됩니다.

동기화할 때는 이전에 로컬에 저장한 주석 이벤트와 해결/다시 열기 변경도 함께 공유합니다. 논문 브랜치·작업 파일·스테이징 영역은 변경하지 않습니다. 원격의 최신 편집을 이미 받은 상태에서 오래된 초안을 저장하면 거절합니다. 아직 받지 못한 상태에서 저장했다면 동시 편집으로 처리하여, 동기화 후 두 버전을 모두 이력에 보존합니다.

네트워크 연결이 실패해도 코멘트는 로컬에 저장됩니다. 리뷰 패널과 상태 표시줄에 동기화 대기 상태를 표시하고 GiTex Output에 오류를 남깁니다. 다음 저장이나 **Sync Comments**로 다시 시도할 수 있습니다.

VS Code 설정의 **GiTex: Auto Sync On Save**를 끄거나 다음 설정을 추가하세요.

```json
{
  "gitex.autoSyncOnSave": false
}
```

이 설정을 꺼도 **GiTex: Fetch Comments**와 **GiTex: Sync Comments**는 사용할 수 있습니다. 이전 `gitex.autoPullOnInteraction` 설정은 폐기 예정이며, 상호작용 시 가져오기는 더 이상 수행하지 않습니다. 기존에 명시적으로 `false`로 설정했다면 새 `gitex.autoSyncOnSave`를 직접 설정할 때까지 자동 동기화를 끈 상태로 유지합니다.

## 문서 커밋별 주석과 동기화

화면의 주석 내용·위치·해결 상태는 현재 문서 커밋에 속합니다. 미래 커밋의 주석 정보를 받아도 현재 커밋의 표시를 덮어쓰지 않습니다. 문서 커밋을 바꾸면 해당 커밋의 주석 버전으로 전환합니다. Explorer와 리뷰 상단에서 커밋 해시를 확인하고, **Paper commit history**에서 이전 기록과 당시의 댓글 버전을 열람할 수 있습니다. 리뷰 창의 초안도 커밋별로 보존합니다.

새 본문 커밋을 감지하면 적용 가능한 이전 커밋의 모든 주석 상태를 새 해시로 기록합니다. 해결된 주석과 대상이 삭제된 주석도 포함합니다. 기본 활성화된 `gitex.autoSyncOnCommit`은 스냅샷 공유 정책을 충족할 때 이 기록과 로컬에 저장된 전체 주석 이력을 자동 push합니다. `gitex.autoSyncOnSave`와 독립된 설정이므로 공유를 완전히 수동으로 하려면 둘 다 끄세요. 본문 입력·저장만으로는 push하지 않습니다. 미저장 본문의 주석 기준과 실제 커밋의 Git 파일에서 만든 기록은 구분해서 표시합니다.

주석은 현재 체크아웃한 문서 커밋 해시에 속합니다. 본문이 원격 최신 커밋과 달라도 경고하거나 업데이트를 요구하지 않습니다. 새 문서 커밋에는 기존 주석 상태를 새 해시에 연결한 사본으로 이어가며, 이전 커밋의 주석은 유지합니다. 새 사본은 최초 공유 시 받아온 부모 버전의 주석 목록을 확정하며, 이후 과거 버전에서 수정하거나 새로 단 주석은 그 과거 버전에만 남습니다. 필요한 경우 수동 이동으로 명시적으로 재연결할 수 있습니다.

동기화는 원격 주석을 자동 pull·병합한 뒤 push합니다. 다른 사용자가 먼저 push하면 자동으로 다시 받아 병합하며 최대 네 번 시도합니다. 네트워크·데이터 검증 실패 시 로컬 작업을 보존합니다. 본문 파일·브랜치·스테이징 영역은 변경하지 않습니다.

현재 커밋에 해당하는 기록이 없는 주석은 **Pending document**로 대기하며 본문에는 표시하지 않습니다. amend/rebase 이후에도 **Move to editor selection**으로 명시적으로 새 커밋에 연결할 수 있고, 이전 커밋 기록은 보존됩니다. 미저장 본문이 있는 편집기는 받은 파일과 정리되기 전까지 이전 커밋을 유지합니다. 자세한 저장·상속·동시 편집 규칙은 영어 문서 [Commit-scoped reviews and synchronization](docs/commit-reviews.md)에 정리했습니다.

## 현재 폴더에 저장소 적용

대상 폴더를 연 뒤 **GiTex: Apply Repository to Current Folder**를 실행하고 SSH/HTTPS URL 또는 로컬 bare 저장소 경로를 입력합니다. 여러 폴더를 연 경우 활성 편집기가 속한 폴더를 사용하거나 대상 폴더를 선택합니다. 상대 로컬 경로는 대상 폴더를 기준으로 해석합니다.

현재 폴더 바로 아래에 `.git`과 원격 기본 브랜치에서 가져온 최신 파일을 만들고, `origin` 및 브랜치 추적을 설정합니다. 프로젝트 하위 폴더를 하나 더 만들지 않습니다. 이후 논문 변경은 Source Control로 처리하며, 기존 리뷰는 **Fetch Comments**로 받을 수 있습니다.

원격 저장소를 임시 작업 폴더에 먼저 받아 충돌을 검사합니다. 관계없는 기존 파일은 유지하고, 같은 디렉터리도 내부 경로가 겹치지 않으면 허용합니다. 가져올 파일과 같은 경로가 이미 있으면 내용이 같더라도 중단합니다. 파일/디렉터리 충돌, 심볼릭 링크를 통과하는 경로, 기존 `.git`, 다른 Git 저장소 내부 폴더, 저장하지 않은 편집 파일이 있어도 중단합니다. 충돌하는 내용은 먼저 저장하거나 다른 위치로 옮겨야 하며, 이 명령은 이를 병합하거나 덮어쓰지 않습니다.

현재 이 명령은 커밋이 있는 기본 논문 브랜치와 일반 파일을 지원합니다. 심볼릭 링크나 서브모듈이 있는 저장소는 **Clone Repository**를 사용하세요. 파일시스템이 하드 링크를 지원해야 하며, 배타적 파일 생성으로 적용 도중 새로 생긴 파일도 덮어쓰지 않습니다. 적용에 실패하면 추가한 파일을 되돌리되, 사용자가 동시에 변경한 파일은 보존합니다.

## 두 사용자로 체험하기

아래는 로컬 임시 폴더에서 사용할 예시입니다. 새 폴더에서 실행하세요.

```sh
git init --bare --initial-branch=main paper.git
git clone paper.git alice
cd alice
git config user.name Alice
git config user.email alice@example.test
printf '\\documentclass{article}\n\\begin{document}\nHello, GiTex.\n\\end{document}\n' > main.tex
git add main.tex
git commit -m "Initial paper"
git push -u origin main
cd ..
git clone paper.git bob
git -C bob config user.name Bob
git -C bob config user.email bob@example.test
```

`alice`와 `bob`을 각각 별도 VS Code 창으로 열고 GiTex를 설치합니다. Alice가 주석을 작성한 뒤 Sync Comments를 실행하고, Bob도 Sync Comments를 실행하면 같은 주석이 나타납니다. 양쪽에서 오프라인으로 답글을 작성한 뒤 동기화해도 답글들이 함께 보존됩니다. 서버에서는 위 `paper.git`을 SSH 등으로 제공하면 됩니다.

**0.15.4부터** 첫 게시 이후 상속되지 않은 미해결 스레드는 Explorer에 **Earlier unresolved**(이전 커밋의 미해결 주석)와 원래 커밋 해시로 표시합니다. 후속 커밋에서도 확인할 수 있지만 현재 버전의 사본·인라인 주석·음영·추정 위치 표시는 만들지 않습니다. 클릭하면 이전 버전의 Review를 읽기 전용으로 열며, 답글·편집·해결은 원래 커밋으로 이동한 뒤 수행합니다. 현재 선택 영역에 명시적으로 연결하려면 **Move to editor selection**을 사용합니다. 이전 버전의 해결 상태를 받으면 미해결 표시가 사라지고 **Resolved · Not inherited** 이력으로 남으며, 다시 열면 **Earlier unresolved**로 돌아옵니다. 현재 버전에 이미 존재하는 스레드의 누락된 이전 업데이트는 **Earlier updates**로 안내하고 현재 토론은 유지합니다.

## 데이터 저장과 동시 작업

| 위치 | 용도 |
| --- | --- |
| 일반 논문 브랜치 | `.tex`, `.bib`, 그림 등 논문 파일 |
| 로컬 `refs/gitex/comments` | 아직 공유하지 않은 주석을 포함한 로컬 주석 이력 |
| 원격 `refs/heads/gitex-comments` | 공동 주석 이력; GiTex 전용으로 예약 |

주석 생성, 답글, 편집, 수동 이동, 상태 변경은 UUID가 있는 불변 이벤트로 저장합니다. 동기화는 양쪽 이벤트를 합친 다음 일반 push를 수행합니다. 다른 사용자가 먼저 push하면 자동으로 받아 병합하고 최대 네 번까지 push를 시도합니다. force push는 사용하지 않습니다. 같은 로컬 저장소를 여러 창에서 수정할 때는 Git ref의 예상 이전 값을 검사해 덮어쓰기를 방지합니다.

해결·다시 열기가 동시에 발생하면 논리 시계와 이벤트 ID 순서로 일관된 최종 상태를 정합니다. 두 상태 변경의 이력은 모두 남습니다. 주석의 작성자 정보는 Git 설정에서 가져오며, 별도의 사용자 인증이나 서명 검증은 제공하지 않습니다.

주석과 답글은 각각 `comments/<commentId>.json` 하나에 편집 이력과 함께 저장합니다. 위치·해결 상태·커밋별 체크포인트는 별도 메타데이터로 기록합니다. 각 기준은 커밋, 문서 해시, 파일 경로, 소스 줄, 논리적 문자 범위와 선택한 텍스트를 기록합니다. 편집 추적은 남은 조각의 오프셋과 소스 파일 전체 스냅샷도 저장합니다. 스냅샷은 `documents/<documentHash>.txt`에 저장하며 동일한 내용은 여러 기준이 함께 사용합니다. 커밋별 기록이 있는 저장소의 메타데이터 형식은 4이며, 개별 리뷰 이벤트는 버전 1을 유지합니다. 과거 저장 형식도 읽을 수 있습니다.

주석 이력에는 주석을 단 문서 스냅샷과 작성자 이메일이 포함됩니다. **첫 push 전** Sync Comments에서 전체 문서 공유와 Git 이력 보존을 안내하고 확인받습니다. `gitex.autoShareUncommittedSnapshots`의 기본값은 `false`이며, 현재 본문 커밋 이력에 없는 스냅샷이 있으면 자동 push를 보류합니다. 수동 Sync Comments에서 해당 push를 승인하거나 설정을 켜서 이후 자동 공유를 허용할 수 있습니다. 검사에는 현재 파일에서 지워진 과거 스냅샷도 포함하며, 승인 전에 새 스냅샷 수와 압축 전 크기를 보여줍니다. [공유 정책](docs/commit-reviews.md#snapshot-sharing-and-size)과 [안정성 검증](docs/stability-validation.md)을 참고하세요. 논문 브랜치만 백업하면 로컬 미공유 리뷰는 포함되지 않으므로 동기화하거나 전체 Git 저장소를 백업하세요. `gitex-comments`를 논문 브랜치에 병합하거나 편집용 브랜치로 사용하지 마세요.

## 개발과 검증

개발·패키징에는 Node.js 22 이상과 npm을 사용합니다. 아래 Makefile 명령에는 GNU Make도 필요합니다. 런타임 npm 의존성은 없습니다.

```sh
make install
make package
```

프로젝트 루트에서 실행하면 현재 버전의 VSIX 파일(예: `gitex-0.15.4.vsix`)이 생성됩니다. `make` 또는 `make help`로 사용 가능한 명령을 확인할 수 있습니다.

| Make 명령 | 실행하는 작업 |
| --- | --- |
| `make install` | `npm ci`로 개발 의존성 설치; 최초 실행 및 의존성 변경 후 사용 |
| `make build` | `npm run compile`로 TypeScript 컴파일 |
| `make watch` | `npm run watch`로 파일 변경 시 자동 컴파일; Ctrl+C로 종료 |
| `make test` | `npm test`로 컴파일 및 핵심 테스트 실행 |
| `make test-extension` | `npm run test:extension`으로 실제 VS Code에서 테스트 |
| `make package` | `npm run package`로 컴파일 및 VSIX 생성 |
| `make clean` | `out/`과 루트의 `gitex-*.vsix` 삭제; 의존성과 VS Code 테스트 캐시는 유지 |

Make는 기존 npm 스크립트를 호출합니다. Make 없이도 표의 npm 명령을 직접 실행할 수 있습니다.

이 프로젝트 폴더를 VS Code에서 열고 **F5 → Run GiTex Extension**을 실행하면 별도 Extension Development Host가 열립니다. 그 창에서 논문 저장소 폴더를 여세요.

```sh
make test
make test-extension
```

`make test-extension`은 공식 테스트 도구로 VS Code 1.90.2를 다운로드하고 임시 저장소·프로필에서 실제 확장을 실행합니다. Linux CI에서는 X 서버 또는 `xvfb-run -a make test-extension`이 필요합니다. `GITEX_VSCODE_VERSION=stable make test-extension`으로 현재 안정 버전에서도 실행할 수 있습니다. `make package`는 공식 `vsce` 도구를 내려받아 VSIX 파일을 만듭니다. Marketplace에는 게시하지 않습니다.

핵심 테스트는 동시 push·편집, 전체 편집 이력, 오래된 초안 검출, push 없는 pull, 로컬 다중 창 업데이트, 오프라인 보존, 서버 거절, 메타데이터 브랜치 충돌, 작업 트리·index 보존, 줄 이동·작은 수정·줄바꿈·삭제·중복 문장 처리와 동시 추적 기준 갱신, 수동 이동 및 전체 이동 전후 이력을 확인합니다. 확장 호스트 테스트에서는 Playwright로 테스트 인스턴스의 로컬 디버깅 포트에 연결해 리뷰 패널의 실제 클릭·펼침에서 원격 요청이 없는지, 저장 및 새 커밋 후 자동 공유, 자동 pull·병합 후 push, 커밋별 표시와 초안 보존, 설정 비활성화, 초안 보존, 해결 상태별 표시, 단일 리뷰 탭 전환, 추적 기준 갱신, 다른 파일로 수동 이동, 저장소 적용 시 저장하지 않은 편집 내용 보호도 검증합니다. 저장소 적용 테스트는 경로 충돌, 동시 파일 생성, 실패 시 되돌리기와 기존 파일 보존을 확인합니다.

저장소 탐색 테스트는 깊은 하위 폴더와 중첩 저장소, 겹치는 workspace 폴더, worktree·서브모듈의 `.git` 파일, Git 내부·bare·임시 적용 폴더·심볼릭 링크 순환 제외를 확인합니다. 확장 테스트는 활성 편집기에 따른 자동 전환, 저장소별 동기화, 초안 보존, 저장소 생성·삭제 후 탐색도 검증합니다.

## 현재 범위

- 주석은 기본적으로 저장 직후 자동 동기화하며, 수동 명령으로도 동기화할 수 있습니다. 실시간 공동 타이핑이나 자동 서버 알림은 없습니다.
- 주석 UI는 LaTeX 소스에 표시됩니다. PDF 위 주석, 문장 단위 의미 분석, LaTeX 컴파일 검증은 아직 없습니다.
- 파일 이름 변경을 자동 추적하지는 않으며, Move Comment to Selection으로 새 파일에 다시 연결할 수 있습니다. 파일 사이 잘라내기·붙여넣기나 문서 버전을 복원할 수 없는 편집에는 수동 재연결을 사용합니다.
- 본문 편집은 원래 작성자의 Git 이메일이 일치할 때만 허용합니다. Git 이메일은 인증된 신원이 아니므로 서버 권한을 대체하지 않습니다. 답글·이동·상태 변경은 협업할 수 있으며 삭제 기능은 없습니다.
- 여러 workspace 폴더와 그 하위 중첩 저장소, worktree, 서브모듈을 지원하며 선택한 파일을 기준으로 저장소를 전환합니다. bare 저장소 자체에는 편집할 작업 트리가 없습니다.
- 주석 이벤트를 메모리에서 합치는 초기 구현이며 Git 명령마다 수집하는 표준 출력과 오류 출력의 합계를 32 MiB로 제한합니다. 대규모 이력 최적화는 후속 작업입니다.
- 서버가 병합을 승인·실행하는 워크플로는 아직 없으며, 논문 병합은 기존 Git 기능으로 수행합니다.
